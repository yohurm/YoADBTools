# ADR-v6-042 — Linux 投屏用 libva 出像素

- **状态：** 草案。未接受。接受前不得改 `linux.rs` 的解码，不得链 libva 的 VLD，不得把本页写成已落地。
- **日期：** 2026-10-09
- **补充：** [ADR-v6-028](ADR-v6-028.md)、[ADR-v6-030](ADR-v6-030.md)、[ADR-v6-032](ADR-v6-032.md)、[ADR-v6-026](ADR-v6-026.md)、[ADR-v6-041](ADR-v6-041.md)、[重设计-文件清单相位与Linux呈现.md](../重设计-文件清单相位与Linux呈现.md) 第 5 节

## 背景

041 交付了 Linux 工作台，并记下主窗 `GtkWindow` 指针。像素仍是占位：`probe().id = vaapi`，`hevc = false`，`spawn_surface` 走 `spawn_unimplemented`。`BindPipe` 把 `PresentBind` 写成 `Failed`，洞里是「没有画面」和「当前平台没有投屏硬解」。会话 `Live` 不代表已经出画。

028 允许 Linux 用 VA-API，并禁止用 FFmpeg / libavcodec 填坑。030 禁止把 OpenH264 打进包里冒充原生后端。032 把 Fit / Convert / Scale / Compose / Present 拆开，禁止 libplacebo、libswscale、libyuv、GStreamer。026 要求有原生表面之后，空态、失败和暂停都画在表面上，WebView 只留透明洞。

本机核对时没有 `/dev/dri`。那是失败关闭的输入，不是改用软解的理由。

## 决策

接受之后才实现。未接受时 041 第 5 条仍然有效。

1. **Linux 的 Convert 与 Present 只活在 `mirror_present/linux/`。** `FramePipe`、`Cmd`、`Stage`、`present_dest` 不动。`Picture` 仍是该后端的关联类型，不提升成跨平台 packed NV12，不进 `yohu-mirror`。
2. **硬解是 libva 自己的 H.264 VLD。** `vaInitialize` 打开设备之后，找 `VAEntrypointVLD` 上的 H.264 profile（High / Main / Constrained Baseline 任一即可）。解码不经过 FFmpeg、libavcodec、`ffmpeg-next`，也不使用 FFmpeg 的 vaapi 封装。scrcpy 的 `--hwdec=vaapi` 不移植。
3. **画面进 041 已记下的 `GtkWindow` 的子控件。** DMA-BUF（`VA_SURFACE_ATTRIB_MEM_TYPE_DRM_PRIME`）或 VA 表面交给这块子控件。子控件盖住 WebKit 透明洞，铺满 avail。可见卡片等于 `present_dest` 的 contain dest。Fit 仍是现成的 `present_dest`，不在子控件里再算一遍 contain。
4. **五层归属。**

   | 层 | 归属 |
   |----|------|
   | Fit | 现成 `present_dest`。不选核 |
   | Convert | `linux/` 里 libva H.264 VLD，1:1 到该后端的表面。不缩放 |
   | Scale | 只在 `linux/`。缩小用面积核，或 GPU 对已导入表面的缩放。不引入 libplacebo / libswscale / libyuv |
   | Compose | 子控件里的卡片 = dest |
   | Present | GTK 子控件翻页。`mirror/painted` 只从这一下发出 |

5. **没有设备就停在呈现失败。** 下面任一成立，`PresentBind` 保持 `Failed`，不创建子控件，不发 `mirror/painted`，`hasFrame` 保持假：
   - 没有 `/dev/dri`
   - `vaInitialize` 失败
   - 打开的设备没有 H.264 VLD 入口
   洞的标题仍是「没有画面」。正文说明没有可用的 VA-API 硬解设备，经 `stage_copy` / `PresentError` 送出，不在 UI 里再写一句。暂停、全屏、指针保持不亮。截图和设备键继续等第一帧。这是产品行为。
6. **`probe` 的身份不变。** `id` 保持 `vaapi`。`hevc` 只在设备打开之后按 HEVC Main + VLD 查询。设备打不开时 `hevc` 仍是 `false`，会话继续按现有计划回退 H.264；回退后若 H.264 VLD 也不存在，走第 5 条，不改用别的解码器。
7. **有子控件之后回到 026。** 空态、失败、暂停改由子控件上的同一份 `stage_copy` 绘制，删掉洞里的 Web 铬。子控件还没建起来时（含第 5 条），继续用第 2 阶段已经落地的洞内文案。
8. **截图。** 只有 Present 已经画出至少一帧，才从最后一帧表面导出。在那之前仍返回「当前平台没有投屏硬解」或第 5 条的设备错误，不写空文件。

## 明确不选

| 方案 | 为何不在这一 ADR |
|------|------------------|
| FFmpeg / libavcodec / ffmpeg vaapi | 028、030、032、041 禁止 |
| 把 OpenH264 打进 `.deb` | 030 禁止用它冒充原生后端。专利授权还要求最终用户单独下载官方二进制 |
| Vulkan Video 作为 Linux 身份 | 覆盖更窄。028 已拒绝用它替换 Windows 路径 |
| GStreamer、libplacebo、WebCodecs、libswscale、libyuv | 032 / 024 已否决 |
| 因为某台机器没有 DRM 就改默认软解 | 把「无设备」和「交付像素」缠在一起 |

## 未决（本草案不接受）

CPU 软解，以及后端私有的 NV12 回退，**不是本草案的决策**。没有 `/dev/dri` 或没有 H.264 VLD 入口时，本草案的行为是 `PresentBind` 失败，不出像素。

若要在硬解打不开时仍出画，必须由 Jessica 另作接受。那份决定要单独写库的专利和再分发，并且不得把 OpenH264 预先打进安装包，不得改 `Caps.id`，不得进入 Windows / macOS，不得把 NV12 缓冲放进 `yohu-mirror`。在她接受之前，实现者不得把软解写进 `linux.rs`。

## 接受之后的顺序

1. `vaInitialize` 探针。有设备才把 `hevc` 从常量改成查询。无设备保持第 5 条。
2. H.264 VLD Convert + GTK 子控件 Present。`mirror/painted` 从这条 Present 发出，`hasFrame` 和 fps 才开始为真。
3. 删掉洞里的 Web 铬。有表面之后，空态 / 失败 / 暂停与 Windows / macOS 同一 `stage_copy`。

## 后果

- 接受前：仓库行为停在 `234eefc` 的占位。本页不授权改代码。
- 接受后：041 第 5 条「投屏像素仍不交付」只对拖出和「无 VA 设备」继续成立。有 H.264 VLD 的机器才出像素。
- 没有 `/dev/dri` 的环境（包括本次核对用的 VM）接受之后仍然是洞里的失败句，不是灰底，也不是软解画面。
