# ADR-v6-040 — 全部流程的标准步骤

- **状态：** 已接受
- **日期：** 2026-10-07
- **关联：** ADR-v6-006、ADR-v6-007、ADR-v6-024、ADR-v6-025、[workbench.md](../workbench.md)、[ipc.md](../ipc.md)

## 背景

界面重建时，WebView 里的 store 被清掉，壳进程里的任务和投屏会话还在。投屏状态栏只在「已出画」时出现，补发又绑在投屏页的 `bindSerial` 上，所以刷新后分辨率和任务会空着。开始按钮还会在命令返回前自己把阶段写成「正在开始」。

各条流程的主人不同。不能收成同一种快照，也不能让每个模块页在 `onMount` 里补应用级事实。

## 决策

每一条流程单独登记：谁触发、主人是谁、界面哪一步可读、禁止什么。新流程先补进这张登记，再写代码。

界面能丢、壳进程还在的事实，只从「界面重建」请回来。只有打开该页才用的，只在「进入视图」读。用户按刷新才重扫。一次点击只发一次命令。

### 壳

**冷启动与整页刷新（同一条 hydrate）。** 触发：`App` `onMount`。主人：各应用级投影。步骤：先 `bindIpc`；再并行读设置、设备目录快照、任务当前列表、投屏当前投影；画完再揭窗（`runBootPipeline`）；揭窗失败则不重扫。禁止在某个模块页的 `onMount` 里补应用级事实。禁止用延时重试顶订阅。

**揭窗后的设备重扫。** 触发：`boot.showMain` 已返回。主人：`device.refresh`，与 core 预热单飞。步骤：只扫目录，不重启投屏、采集、浏览。周期自动刷新是这条的重复，不是第三条路。禁止在 hydrate 的「读快照」里跑 adb。

**退出。** 触发：关窗。主人：根取消令牌。步骤：取消 → 任务收敛，超时杀 adb 进程树 → 设置 flush。禁止界面各自停会话。

**窗口三键与最大化。** 触发：标题栏。主人：窗口 store 转发系统窗口。步骤：一次 invoke，状态跟系统回读。禁止界面记一份「已最大化」当真。

**未捕获错误。** 触发：`window.error`。步骤：写应用日志并 `system.reportError`。不改任何会话投影。

### 设置与身份

**读身份与设置。** 触发：hydrate。主人：`system.info`（身份、路径、全量设置）。步骤：一次读，填 `settingsStore`；标题栏、状态栏版本、关于页都读这份。无单键 get。失败保留主错误，不假装已加载。

**改一项设置。** 触发：设置页。主人：`settings.set`。步骤：写入后 `settings/changed` 带全量快照，store 整份替换。立即生效的项在这次替换里应用；标成重启或下次采集的项不在界面里再解释一遍。禁止模块另订一份设置。

### 设备

**读目录。** 触发：hydrate。主人：`device.list`（上次扫描结果，不跑 adb）加 `device.status`。步骤：先目录，再运行时。空目录就是没有设备。

**重扫目录。** 触发：刷新按钮、揭窗之后、自动周期。主人：`device.refresh`。步骤：单飞；扫描中不把已有卡片清成空；结果替换目录；掉线的 serial 停采集、投屏、浏览并推 `device/offline`。禁止模块自己 `setInterval` 打 dumpsys。

**运行时状态。** 主人：`DeviceStatusHub`。步骤：只对 Online 采样；内容变才推 `device/status`；丢了用 `device.status` 对账，hydrate 用的就是这一次。夜览按钮写 `device.setNightMode`，Hub 更新缓存再推。禁止投屏页自己轮询深浅色。

### 任务

**当前任务。** 触发：hydrate，以及之后的 `task/summary`。主人：任务中心。步骤：hydrate 读一次当前列表（`task.list`，与事件同一结构）；之后只信推送，推送是全量替换。禁止界面合并出第二份任务表。

### 更新

**查看通道。** 触发：关于页打开。主人：`update.info`。步骤：进入该页读一次，不进 hydrate。

**检查、下载、安装、取消。** 触发：关于页按钮。主人：`update.check` / `download` / `install` / `cancel`。步骤：阶段只跟 `update/progress`；终态必达，下载进度可丢。界面不在 invoke 返回时自己把阶段写成「下载中」。已有的「正在安装则忽略非安装进度」保留，这是同一投影的门闩，不是第二份阶段。

### 终端

**命令库。** 触发：进入终端页。主人：`commandlib.load`。步骤：视图挂载读一次；保存是 `commandlib.save` 全量提交。取消编辑不写盘。不进 hydrate。默认展开是设置，不是库文件。

**导入。** 触发：确认导入。步骤：`preview` 只读；`apply` 才写。预览不改库。

**单条执行。** 触发：发送或点库里的命令。主人：`terminal.exec`。步骤：一次输入对应整段输出；不在界面配置成功失败正则。占位符填值只在界面，填完仍走这一条。

**组与块。** 触发：运行组或块。主人：`group.run` / `block.run`，取消 `group.cancel`。步骤：组内串行、不因失败停、条目之间不加间隔；进度只信 `group/progress`，回流成输入输出行。禁止界面再排一份执行队列当真。

### 文件

**浏览会话。** 触发：进入文件页或换设备。主人：`files.session.attach`（已 Live 则 adopt）。步骤：拿到 `generation` 再 `files.list`。离开或换设备 `detach`。不进 hydrate。attach 成功只表示提交时已 Live，不表示稍后仍 Live；列表失败按该次错误显示。

**刷新目录。** 触发：刷新或路径变化。步骤：用当前 generation 再 list 一次，只换这份列表。禁止为此重开会话。

**上传、下载、取消。** 主人：`files.push` / `pull` / `cancel`。步骤：进度只信 `transfer/progress`（进行中可丢，终态必达）。界面不把「已完成」写在 invoke 返回上。

**删除、新建、拖出。** 各一次命令。删除先经 core 安全根。成功后用同一次 list 刷新，不在界面里假删一行当结果。

### 日志

**采集。** 触发：窗口点开始或停止。主人：`log.capture.start` / `stop`。步骤：已 Live 则 adopt；界面以 `log.capture.status` 对账，不在 start 返回时把窗口标成采集中。切焦点不停其他设备。掉线只停该 serial。

**补行。** 触发：溢出或窗口第一次开始。主人：`log.replay`。步骤：从 `fromSeq` 补，不另开一路 logcat。hydrate 不恢复「开了哪些 Tab」；那些是视图停留。

**清缓冲、导出。** `log.clear` / `log.clearDevice` / `log.export` 各一次。导出读环，不在界面拼文本当文件。

**进程与包名。** 进入过滤需要时 `log.processSnapshot` / `log.packageSnapshot`。周期进程索引是采集侧的推送，界面不自己轮询 `ps`。

### 投屏

**当前投影。** 触发：hydrate，以及 `mirror/state`、`mirror/painted`。主人：壳把槽位和呈现闩合成 `MirrorSessionSnapshot`（阶段、世代、尺寸、编码、控制通道、已出画、上一拍 fps、暂停、全屏、错误）。步骤：hydrate 读 `mirror.session` 一次；之后事件只改这行的对应字段。`has_frame` 和 fps 记在呈现服务上。离开投屏页拆 HWND 不清这两项；`stop` 和掉线才清。状态栏：Live 且有尺寸就显示 `宽×高`，fps 大于 0 才接上。禁止用界面里的 `hasFrame` 把整行藏掉。

**开始与停止。** 主人：`mirror.start` / `mirror.stop`。步骤：界面不先写「正在开始 / 已在播 / 空闲」。新会话只信随后的 `mirror/state`。已在播再开始则 adopt，返回前推这行 Live，调用方用它覆盖。停止只信终态。命令抛错时，界面记下这次失败。

**仅显示。** 打开 = `mirror.closeControl`，随后把这行 Live 再推一次（通道已关）。投影里通道关掉就是仅显示，不另记一份会话事实。关闭 = 停再开，仍走开始。开始前的「下次不要控制」只留在界面，会话出现后以投影的 `control` 为准。

**暂停与全屏。** 只改 layout 旗标。呈现留下上次可回放 layout，投影带回这两个旗标。按钮跟投影。

**舞台开关。** 触发：当前模块是不是投屏。主人：`mirror.present.setActive`，只由工作台调用。步骤：模块身份没变就不调用；已经是目标开闭就不 `shutdown`。离开在淡出之前关。未激活时 layout 丢弃。回来用上次可呈现 avail 建窗。

**可用区、指针、按键、截图。** 视图只报 avail。指针与 layout 同一坐标系，界面不算 dest。注入只在投影允许操作时送出。截图要求投影已出画，像素从呈现的最后一帧取。质量走设置，夜览走设备 Hub，都不写投屏阶段。

## 不做什么

- 不合成一个通用 invoke，不让各模块共用同一种快照结构。
- 不把视图停留（命令库、文件路径、日志 Tab、更新关于页）放进启动。
- 不把设备周期扫描推广到投屏或日志。
- 不新增 `mirror.status` 轮询，不保留 `mirror.sync`。
- 不在界面预写主人的阶段字段。
- 不删各模块文档里的「设计前」档案。

## 验收

- hydrate 在揭窗前并行读设置、设备目录、`task.list`、`mirror.session`；揭窗失败不 `device.refresh`。
- 刷新后任务列表与投屏 Live 尺寸仍在；fps 为 0 时只显示分辨率。
- `mirror.start` / `mirror.stop` 返回前不把阶段写成 starting / live / idle。
- 重复 `setActive(false)` 只在第一次从开到关时 `shutdown`。
