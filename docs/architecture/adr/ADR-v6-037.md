# ADR-v6-037 — 命令库拖入导入

- **状态：** 已接受
- **日期：** 2026-10-05
- **关联：** ADR-v6-009、ADR-v6-011、[modules/terminal.md](../modules/terminal.md)、[ipc.md](../ipc.md)

## 背景

命令库需要从外部 JSON 追加命令。文件管理已经用 `YoPanel edge=drop` 表示投放。把文件模块的目录落点、设备闸门或 `drop-session` 接到命令库上，会把两个模块焊在一起。

外部样例（如 `Nori_CommandLibrary.json`）正文是 schema 3 的组与条目，但可以不写 `schema_version`。产品库磁盘加载仍只认显式的当前 schema。

## 决策

1. **投放铬**只复用 `@yohu/ui` 的 `YoPanel edge=drop`。栏内命中留在终端 `library-drop.ts`，订 `@yohu/api` `onNativeDragDrop`。物理点除以 scale、矩形包含走 `@yohu/ui` placement，不从文件模块的 `drop.ts` 抄。指针落在命令库栏内才画虚线、才解析。执行结果栏和命令管理三栏不是投放面。
2. **解析与合并**在 `yohu-domain`：`screen_import_paths` 只返回空批次或非 JSON（`ImportScreen`），`parse_import_text` 补缺省 schema 并收成库，`combine_imports` 拼多文件再校验，`preview_import` / `apply_import` 对照当前库。壳 `library_store` 只按通过筛选的路径读文本，并把空路径、非 JSON、非命令库收成分类，不把领域文案再装进字符串错误。IPC 边界读这三类的领域 Display。终端视图不预判扩展名，预览失败走这条文案。产品库加载把反序列化结果交给 `from_dto`，壳不比较 schema 号；缺字段或校验失败则备份后写默认库，不补缺省 schema。显式其他版本、同批 id 冲突整批拒绝，不写产品库。
3. **确认**在终端 `ImportDialog`，结构是复核单，不是加宽的提示框。钉住范围（文件里有什么）和决策行（全选 + 将新增/覆盖）。滚动区按组：组行用 `YoCheckbox tone=section`，条数贴在组名旁，行尾才是「已在库中」；条目缩进一列勾选，种类图标在盒与名称之间。组行不套 `YoSubheader`，避免标题和复选框各说一遍名字。页脚主按钮写出将提交的条数。宽高由勾选列、命令库栏宽的身份轨、状态轨和可见行数相加（`IMPORT_DIALOG`），不取弹出框 400 帽。`commandlib.preview` 不写盘。用户用全选和条目多选确认后，`commandlib.apply` 重读同一批路径，只接受条目 id，不接受 UI 回传的 template。已存在的 id 原地覆盖；新 id 追加。命令管理窗口开着时 UI 拒绝预览和提交。

## 不做什么

- 不引用 `@yohu/module-files`，不抽文件模块的 `drop.ts`。
- 不给 `YoCheckbox` 加半选态。
- 不改产品库加载：缺省 schema 的磁盘文件仍备份后写默认库。
- 不在导入对话框里展开命令块步骤，也不改命令管理草稿。

## 验收

- `cargo test -p yohu-domain --lib import` 覆盖预览标记、追加、原地覆盖、未知 id。
- `cargo test -p yohu-adbtools --lib library_store` 覆盖缺省 schema 的导入，以及产品库加载仍拒绝缺省 schema。
- 终端单测：勾选级联、栏内命中、对话框不引用文件模块。
