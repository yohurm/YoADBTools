# ADR-v6-050 — 日志数据面视口化重构（Rust 侧过滤 + 分页，UI 只持视口）

- 状态：已采纳（2026-11-23）
- 取代：ADR-v6-049「P1-1 决策：保留 UI 全量文档」；日志数据面范围内取代 ADR-v6-006「过滤只在 UI」的存储实现方式（过滤表达式仍由 UI 下发，执行在 core）
- 关联：ADR-v6-006/007/021/041/046/047/048/049

## 背景

实时取数已改为「设备环水位 + 按 seq 拉原始行」（ADR-v6-049）。但 UI 仍为每个窗口保留**过滤后的全量文档**（上限 `buffer_capacity`），正文最多三份（Rust 环 + JS `LogLine.msg` + 编辑器 `DocMessage.text`），窗口多时内存随缓冲线性放大。旧文档 `日志消费投影重设计-v6.md`、`日志系统架构审查-2026-11-20.md`、`日志实时取数-现状与LogCat对齐.md` 描述的是旧 `log/hits`/全量文档模型，已删除。

## 决策

**日志数据面改为视口化**：过滤与分页在 core 执行，UI 每个窗口只持有「视口窗口 + 前后缓冲」的行（O(视口)），滚动/换过滤/实时增量都通过分页命令取数。

1. **core 暴露过滤分页查询** `log.query(serial, filter, from_seq, to_seq, limit, direction)`：
   - core 用 `yohu_domain::log_filter_matches` 在环上过滤（不把过滤搬进采集，不改变环语义）。
   - `direction=forward`：在 `[from_seq,to_seq]` 内取最早 `limit` 条命中；`backward`：取最晚 `limit` 条命中（结果按 seq 升序返回）。
   - 返回 `LogQueryPage{serial, lines, has_more, ring_first_seq, ring_last_seq}`；`has_more` 表示该方向是否还有更多命中。
2. **UI 窗口模型**：
   - 每会话持有 `rows`（视口窗口，≤ `WINDOW_MAX`，默认 2000）而不是全量文档；`DocMessage.text` 只对视口行格式化（消除第三份正文）。
   - **实时**：`log/appended{serial,last_seq}` 只在水位前进且窗口处于跟随态时触发一次 `forward` 查询（`from_seq=lastSeen+1, to_seq=last_seq`，过滤=窗口过滤），追加并裁头。
   - **滚动**：到顶→`backward` 取上一页前插；到底→`forward` 取下一页追加；页大小 500，`has_more` 决定是否还能继续。
   - **换过滤/首次开始/恢复**：`backward` 从 `ring_last_seq` 取尾部 `WINDOW_MAX` 命中作为新窗口；不把整环拉进 UI。
   - 暂停/离开底部：只记水位与 pending，不拉正文；恢复时 `forward` 补齐到当前水位（受 `WINDOW_MAX` 裁剪）。
3. **删除的旧路径/数据**：
   - UI 全量文档（`visible` 上限 = `bufferCapacity`）、`log.range` 全量原始行拉取到 UI 再过滤的主链（`viewport-page` 全量重建、设备泵向所有窗口分发全量原始行）。
   - `DocMessage.text` 对全量行预格式化。
   - 三份旧审查/设计文档（见背景）。
4. **不做双轨**：旧 `log.range` 保留为导出/诊断用的原始读（不参与实时文档）；实时文档只走 `log.query`。

## 契约

```rust
pub enum LogQueryDirection { Forward, Backward }

pub struct LogQueryRequest {
    pub serial: String,
    pub filter: LogFilter,
    pub from_seq: u64,   // 游标下界（含）
    pub to_seq: u64,     // 快照上界（含），调用方传当前 ring_last_seq
    pub limit: u32,      // 单页命中上限
    pub direction: LogQueryDirection,
}

pub struct LogQueryPage {
    pub serial: String,
    pub lines: Vec<LogLine>, // 始终按 seq 升序
    pub has_more: bool,
    pub ring_first_seq: u64,
    pub ring_last_seq: u64,
}
```

## core 实现要点

- 环上按 `seq - 最旧seq` 下标分块扫描（复用 P0-1 的下标窗口），锁内只克隆 `Arc` 指针，过滤与 `to_wire` 在锁外。
- 过滤稀疏时 backward 可能扫较长前缀：先用 `to_seq` 夹到 `ring_last_seq`，每块 1024 行；`has_more` 由是否还有未扫命中决定。后续可加「按过滤键的 LRU 命中索引」作为纯优化（不改契约）。
- 分页结果是小页（≤2000 行）→ 走 JSON 即可；导出仍走 `log.export` 流式过滤。

## UI 视口模型

- 状态：`rows`、`firstIndex/lastIndex`（命中序号）、`ringFirst/ringLast`、`following/frozenThroughSeq`、`paused`、`pendingCount`。
- 面板只渲染 `rows`；滚动触发页请求；DOM/编辑器件数只与视口相关。
- `signalCount` 等派生量按窗口行计算；全量统计若需要由 core page 的 `total`（后续字段）提供，不在 UI 全量持有。

## 迁移阶段

1. **S1（已落地）**：协议 `LogQueryRequest/Page/Direction` + core `query_filtered` + 单测（forward/backward/has_more/过滤/越界）。
2. **S2（已落地）**：`log.query` 命令（async spawn_blocking）+ `@yohu/api` 类型/调用。
3. **S3（已落地）**：UI store 视口窗口（`WINDOW_MAX=2000`）：loadPage 取环尾一窗、catchUp 水位增量、`loadOlder/loadNewer` 滚动分页；删除设备原始行泵与全量文档路径；store/panel 用例重写（logs+api 681 全绿）。
4. **S4（进行中/收口）**：旧文档已删除、模块/IPC/ADR 同步；全量门禁与真机压测见下。

## 真机压测（2026-11-23，CDP 驱动 UI invoke）

- 单设备 `log.query`：尾窗 **200 行（seq 2881–3080）/ 8ms**；头页 **200 行（seq 0–199）/ 7ms**；环 `last=3080`。
- 3 设备并行：各 **200 行**（ring_last 14760 / 11126 / 5218），单次 **8–10ms**。
- 前端全量 Vitest **2858 通过 / 1 环境抖动**（mirror 单跑 40/40）、`typecheck=0`、`lint` 通过；Rust `clippy=0`、`yohu-logsrv=94+13+6`、`yohu-protocol=59`。

## 取舍

- 换过滤不再「零 IPC 即时重筛」，改为一次 core 查询（10 万行毫秒级 + 小页返回）；可接受。
- 滚动跨页有一次 IPC 延迟；页大小 500 与前后缓冲隐藏边界。
- 内存从 O(buffer_capacity × 窗口数) 降到 O(WINDOW_MAX × 窗口数)；代价是 core 承担过滤扫描。
