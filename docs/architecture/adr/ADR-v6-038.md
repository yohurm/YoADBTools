# ADR-v6-038 — 盒子归组件，数据链路不改层

- **状态：** 已接受。调用方盒子与快捷键身份已回到拥有者；产品数据链路未改层。
- **日期：** 2026-10-05
- **关联：** ADR-v6-005、ADR-v6-011、ADR-v6-012、[layers.md](../layers.md)、[youi.md](../youi.md)、[modules/](../modules/)

出处：仓库已声明的桌面栈（View → store → `@yohu/api` → commands → domain / capability）与 YoUI L0–L5。组件之间只依赖更低层的公开面；同一视觉决策只有一个来源（YoAgentDocs 组件库「禁止耦合」）。不新造第三套层名。

## 背景

解耦被做成了「调用方不再写出某个 class」：进度条高度改成 `size`，导入行用外包槽去拉复选框，日志表头为了不读滚动条而多一个裁切盒，设备栏折叠和参数描述空槽也准备用新 prop / 回调把选择器藏起来。选择器没了，边界没变——调用方仍在决定别人的盒子。这是在旧边界上加固。

未写完的折叠 `flex` 与列表 `onOccupied` 已撤回，不留半截 API。

## 决策

1. **产品数据不改层。** 各模块主路径保持下文「设计后」。不把填充、判定、安全根、采集槽位、解复用抬进 View，也不把页面状态放进 YoUI。
2. **盒子归拥有它的组件。** 高度、伸缩、侧轨、空槽是否占位，写在该组件自己的 L2 不变式和 L4。调用方只声明这份不变式里已经有的配置，并且只排自己的槽。
3. **禁止用新 prop 换掉选择器。** 调用方点 `.yohu-*` 去改别人的盒，和为了删掉这个选择器临时加的 `size` / 外包 / 裁切盒 / `flex` / `onOccupied`，同属一条错链路。替换时旧选择器和临时 API 同一刀删除，不双轨。
4. **已有不变式继续用。** 操作面板是 `YoPanel role=ops`（顶栏素底、内容区画布）。操作项功能是滚动族 `opsListBindings` 投影到 `YoVirtualList`，行内容是列表族 `YoOpsItem`。换位源槽是 `resolveReorderSlot`。这些不是本条要拆的包装。

## 设计前（错的一跳）

```text
调用方发现盒子不对
  → CSS 或脚本点别人的公开根 / 内部槽
  → 再加只服务这一处的 prop、外包或回调，让选择器从门禁里消失
```

问题出在第二跳：状态（多高、是否拉满、侧轨垫打在哪、空槽还占不占位）没有回到拥有该盒子的组件。

## 设计后（产品主路径，保持）

```text
终端发送
  点叶子 → store.enqueue*（填充在 store）→ sendAll → terminal.exec / block.run / group.run
  → commands 转发 → domain GroupExecutor → adb Runner
  导入：拖入路径 → store.previewImport / applyImport → commandlib.preview / apply → 内存库投影
  命令管理：open(library) 深拷贝 → 草稿 store → commandlib.save 全量提交

文件浏览
  AddressSlot Enter → listingStore.goTo
  → path-resolve 一次 → files.list
  → commands require_online → browse_runs → FileBrowser（SafetyRoot）
  → FileError 分类 → ipc 码 → fault 文案

日志采集
  窗口 hold 0↔1 → log.capture.start/stop
  → CaptureSlot + generation → 每设备一路 logcat
  → Batcher → 环；UI ingest 入镜像，panel 按 fromSeq 投影
  导出：log.export → capture_runs → 环快照 + domain 过滤

投屏
  mirror.start → DecodeSeat + FramePipe
  → 壳 Fit / Convert / Scale / Compose / Present
  离开模块只毁表面，座与槽留下

设备
  adb devices -l → device_catalog
  → Online 才进 DeviceStatusHub
  → deviceStore 投影 → DeviceRail
  模块不扫设备、不轮询夜览

更新
  设置关于 → updateStore → update.check / update.download
  → commands → update_runs → yohu-update 编排
  → yohu-textparsing（说明）与 yohu-download（HTTP）
```

命令库检索把 DTO 编成 `SearchDocument` 后走 `yohu-search` 的公开面；判定仍不进 domain 对引擎的依赖。

| 投屏公开句 | 通道 IO 与「无 -T」都写成「投屏设备通道失败」 | 只有 `Adb(Io)` 用这句并去掉载荷；`UnsupportedShell` 仍是「浏览 shell 不可用」 |
| 更新失败句 | `reqwest` 整句塞进 `Network`，界面再加「检查更新失败」；下载也走这句 | `CheckFailed` / `BadHeader` / `DownloadFailed` 各一句；界面只显示这条 |
| 下载引擎网络 | `DownloadError::Network(String)` 装 reqwest 整句，空转用 `"no attempt"` | 单元 `Network`，句子「下载失败」；重试用上一回的真实错误 |
| 更新响应解析 | serde 整句塞进 `Parse(String)` | 单元 `Parse`，句子「解析更新响应失败」 |
| 更新未变化 | 304 的句子塞进 `Platform(String)` | `NotModified`：「更新元数据未变化，请稍后再试」。平台 `message` 仍留在 `Platform` |
| 命令任务汇合 | `JoinError` 整句装进 `TerminalEvalError::Join(String)` | panic 是「命令任务异常结束」；任务被中止是「命令任务已取消」 |
| 候选扫描失败 | 各候选 Display 拼进 `ToolUnavailable` | `CandidatesFailed`：「全部 adb 候选扫描失败」。明细只留在扫描日志 |
| 更新动作分类 | 打开下载、启动安装、定位产品目录都写成「写入安装包失败」 | `OpenFailed` / `LaunchFailed` / `HostRoot` 各一句。`Io` 只保留安装包或脚本的写入，载荷是操作系统原文 |
| 投屏故障分类 | 协议、编码、server 失败把句子塞进字符串，再用字符串相等区分 | `ProtocolFault` / `CodecFault` / `ServerFault`。用户句就是该类别的句子，不再加「投屏协议错误」前缀 |
| 截图呈现错误 | `PresentError::Internal(String)` 把后端名、PNG 和显卡原文当成用户句 | `Unimplemented` / `ScreenshotWrite` / `ScreenshotRead` 各一句 |
| 日志导出目录 | 没给目录时塞进 `io::Error`，界面再加「导出失败」 | `ExportDir`：「未指定导出目录」。导出结果只显示这一句 |
| 命令回退 | `pm`/`cmd uimode` 与回退命令的 stderr 拼进同一次 `BadExit` | 用户句只带收尾那次的退出码和 stderr。前置失败写在日志 |
| 采集跟流收口 | `Err(_)` 把超时、截断、通道失败和掉线以外的运输错误收成同一桶，日志也不留原句 | 只有 `DeviceOffline` / `NotOnline` 停槽。其余变体点名后仍同世代重启，日志带该错误自己的句子 |
| 命令库读写 | `LibraryStoreError::Io(String)` 把操作系统或序列化原文当成用户句 | `Io`：「命令库读写失败」。原文只留在日志 |
| 设置写入 | 校验失败和写盘失败都变成 `String`，再一律标成参数非法 | 校验仍是领域句、`InvalidArgs`。写盘是「无法写入设置文件」、`Internal` |
| 拖出 OLE | `OleFailed(String)` 把 HRESULT 调试文本写进「DoDragDrop 失败」 | `OleFailed`：「拖出失败」。返回码只留在日志 |
| 投屏组件缺失 | 用户句带开发脚本名和本机路径 | `ServerMissing`：「缺少投屏组件」。路径只留在启动日志 |
