# ADR-v6-047 — 日志模块深层架构：状态机闭合、数据链路闭环与单一数据源

- **状态：** 已采纳
- **日期：** 2026-11-19
- **关联：** ADR-v6-006/007/016/021/041/046、[modules/logs.md](../modules/logs.md)、[ipc.md](../ipc.md)

## 背景

ADR-v6-046 完成后，日志模块分层已解耦、无死双轨，但**逐部件状态机、数据链路闭环、单一数据源**仍有缺口：两处 P0 同源不同层（「登记/索引」与「事件/追加」缺原子性）——Rust `WindowBook::bind` 与 `commit` 可交错丢行/重复；壳 `capture_runs.register` 与 `finish` 可交错致任务永久 Active。另有 19 项 P1（隐藏状态、转移缺口、多持有镜像、死状态、热路径冗余）与 50 项 P2。

## 决策

### 1. 状态机闭合（逐部件）

- **采集槽位**（`slots.rs`）：`Empty | Starting(gen) | Live(gen) | Stopping(gen)`，**Empty 显式**（携带 `last_generation`）；不变量 `debug_assert`：每 gen 至多一次 Stopped、仅 Live adopt、三路句柄（capture/index/batch）同代际同生共死。
- **跟流**（`follow.rs`）：`AttemptBudget` 连续可恢复失败计数 + 指数退避（常量入 `limits.rs`）达阈值升级 `Terminal` 走掉线收敛；`Exited{code:0}` 计入；`skip_resume` 对空 ts 系统行对称。
- **窗口索引**（`windows.rs`）：`bind` 在锁内取 `binding_through = ring.next_seq()` 水位并整体替换；`commit` 仅接受 `seq >= binding_through`，`prepare` 每命中携带窗口世代；`release` 推进 epoch。不变量：`hits == 环 ∩ filter ∩ seq>=from_seq`。信号改由 UI 从可见行派生（删 `Window.signals`）。
- **环/容量**（`ring.rs`/`ring_store.rs`）：容量唯一 owner = `RingStore`，`set_capacity` 遍历所有环下推 + `debug_assert`；`RingBuffer` 容量只读镜像；`for_each_from(from, through)` 有固定快照上界、≤512 分块；读路径 `try_ring` 不懒创建。
- **进程索引**（`index.rs`）：`ProcessIndexSnapshot.generation` 必填；周期路径唯一事件生产者（首拍延后一周期）。
- **任务账本**（`run_ledger.rs`，壳）：键 `(serial, generation)`；`begin`（在途）→`register_with`（锁内撤在途 + 查墓碑 + 建任务）→`close`（锁内取任务或写墓碑）；墓碑数受在途数约束；`sweep` 自愈；`TaskCenter` 单 drainer 串行推送 + 终态回收。
- **UI 采集相**：唯一 owner = `capture-orchestrator`（`markStarting/markLive/markStopped`）；`follow-state` 只写 `following/frozenThroughSeq`。
- **UI 跟滚/游标**：`following/frozenThroughSeq` owner = `follow-state`（`panel.applyAppend` 消费冻结上限）；`fromSeq` owner = `follow-state`；删 `hitTotal/pageIndex/placePage`（滚动比例 = `visible.length`）；`docShift` 整替换归零、追加裁头累加；`pendingCount` 单点增量 + 三处归零；`signalCount` 只由可见派生。
- **UI 编辑器**：`colChars` 移出 `formatOptionsKey`（拖宽仅 end 提交）；`appNamesRevision` 进格式键；`rowChars` 用与 VirtualList 同一内容盒宽；`documentRef` 有 detach；常量单源（级别/PID/Tag 档）；`Document.sync` 把「淘汰+追加」作为一次显式操作交 Board。

### 2. 数据链路闭环

采集 start/stop/adopt/restart/offline、hits→文档、过滤重建、暂停、清空可见区、清设备缓冲、导出、掉线——全部闭合；导出未登记 serial 报 `WindowNotRegistered`（不静默写空）。

### 3. 单一数据源契约

| 语义 | 唯一 owner |
|---|---|
| 日志全文 | 设备环 `RingBuffer` |
| 环容量 | `RingStore.capacity` |
| 信号计数 | UI 可见行派生（core 不再并行计数） |
| 世代 | `CaptureSlot.generation` → `CaptureState.generation` → `device-projection`（只升不减） |
| 任务账本 | `RunLedger`（键 `(serial,gen)`） |
| 采集相 | `capture-orchestrator` |
| following/frozen/fromSeq | `follow-state` |
| 文档行数 | `visible.length` |
| 文档文本 / 复制载荷 | `DocMessage.text` / `CopyMessage.text` |
| 格式键 | `formatOptionsKey`（不含 colChars、含 appNames revision） |
| 宽度尺 | `measureChPx` + VirtualList 内容盒 |
| 默认导出目录 | `capture_runs::default_export_dir` |
| 设置键名 | `SettingKey` 派生的 `SETTING_KEYS` |

### 4. 契约与冗余

删除死契约/死代码：TS `LOG_PAGE_LINES`/`formatLogLine`/`formatDateTimeFromMs`/`isLogLevelLetter`、`LogPage/LogHits.signals`、`hitTotal/pageIndex/placePage`、`sessionEmptyWait`、`applyHits` 不可达分支等；`logFilterMatches` 收敛为公开 `matchesWireFilter(line, filter)`；`HISTORY_PID_CAP` 由 fixture/常量锁；事件名/墙钟/过滤/级别/默认设置维持双端 testdata 锁。

## 后果

- 采集中改过滤/迟到 Stopped/掉线不再丢行、重复或任务永久 Active。
- 每个语义数据有唯一 owner；旧的「多处镜像/派生重复」清零。
- 拖列宽不再触发全表重排；进程索引晚到使 App 列正确刷新。
- 门禁：`cargo build/test/clippy` 与 `pnpm typecheck/test/lint` 全绿；深审 P0/P1 全部闭合（见 `.tmp-logs-review/deep/`）。

## 不引入

不引入兼容层、双轨 API、永久适配器、预留死字段；不把任何 P0/P1 降级为「非阻塞观察」。
