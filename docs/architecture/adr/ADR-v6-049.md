# ADR-v6-049 — 日志实时取数：水位信号 + 环形缓冲游标拉取（对齐 LogCat）

- 状态：已采纳
- 日期：2026-11-20
- 关联：ADR-v6-006/007/021/041/046/047/048、[日志实时取数分析](../../reviews/日志实时取数-现状与LogCat对齐.md)

## 背景

实时更新靠 `log/hits` 携带正文批次推给 UI；`try_send` 满即丢（丢推送不丢环），UI 只在整页 `log.window.bind` 时读环。切应用/后台使事件队列满 → UI 文档缺一段，环淘汰后不可补。Android Studio Logcat 是「IDE 内消息环/文档为数据源，视图去读」，与我们的「推送正文」模型不同。

## 决策

1. 环形缓冲是唯一实时数据源；UI 每窗口持**全局 seq 游标**。
2. `log/hits` 改为**不含正文的水位信号** `LogHits{serial,window_id,total,appended,last_seq}`；`last_seq` 是本窗口命中最新 seq。
3. UI 收到信号后调用 `log.range(serial, from_seq, limit)` 从环**按 seq 拉原始行**，过滤仍在 UI（ADR-v6-006）；拉齐到 `last_seq`。
4. 丢弃信号只影响延迟：下一次水位更高即可一次补齐；容量内不丢。
5. 删除 `LogHits.tail` 与 `Batcher` 的正文聚合/按字节切分；`batcher` 只聚合水位信号。

## 后果

- 切应用/后台丢推送不再丢日志（受环容量约束，ADR-v6-021）。
- `log/hits` 体量从「正文数组」降为「水位」；事件通道压力显著下降。
- 初始页仍走 `log.window.bind`（快照读取）；后续可继续收口 WindowBook。

## 不引入

不引入兼容层；不做「推送正文 + 拉环」双轨。过滤仍在 UI，不搬进 core。
