# ADR-v6-048 — 日志消费投影：连续 seq 游标与单一文档状态机

- 状态：已采纳（Stage 1+2 落地；Stage 3 另立范围）
- 日期：2026-11-20
- 关联：ADR-v6-006/007/016/021/041/046/047、[日志消费投影重设计](../../日志消费投影重设计-v6.md)

## 背景

`log/hits`（增量）与 `log.window.bind`（全量前缀快照）两条通道在 IPC 上无序，窗口文档位置没有单一所有者，靠 `viewport-page.pageGen` 与命中 `bumpPage` 临时互斥，再由 `applyPage` 盲替换。任一交错即丢行；溢出只能被动整页重绑；三处重复 head-overlap、两套文档增量实现。

## 决策

1. **连续 seq 游标为文档唯一位置契约。** `lastSeq` 单调；命中 `tail[0].seq != lastSeq+1` 即空洞，主动 `reload` 对账，不静默丢弃。
2. **单一对账原语** `ui/.../logs/src/stream/seq.ts`：`lowerBoundSeq/findHeadOverlap/isSuffixAppend`；`panel-projection`/`document`/`board` 共用，禁止再写第二份。
3. **删除 `bumpPage/pageGen` 的命中参与**；`viewport-page` 只用请求序号丢弃过期页响应。
4. **`applyPage` 按 seq 对账**：页为真前缀，保留 `seq>页末` 且命中当前过滤的已画行。
5. **空洞自愈** `capture-subscriptions.healGap`：不依赖 `log/overflow` 事件（其可能延迟/丢失）。
6. **Stage 2** 把文档状态（rows/游标/pending/signal/docShift/follow）收进纯 reducer `stream/log-window-reducer.ts`，`panel-projection`/`follow-state` 变薄装配，删除两套增量实现。
7. 采集平面 `yohu-logsrv` 不改内部，只暴露稳定 seq 契约。

## 后果

- 溢出/换过滤/并发命中的丢行与重复由「连续 seq + 按 seq 对账」结构性消除，不再依赖 overflow 事件。
- 文档位置有唯一所有者；重复算法收敛为一份。
- 门禁：`logs` 351 用例、tsc、lint 通过；`cargo test -p yohu-logsrv` 保持全绿（采集平面未改）。

## 不引入

不引入兼容层、双轨、第二套文档缓存；分阶段不是半成品交付，每阶段另声明并整理到干净。
