# ADR-v6-035 — GitHub 更新 Provider 分层（免 REST 优先）

- **状态：** 已接受
- **日期：** 2026-09-24
- **关联：** ADR-v6-022、ADR-v6-034、[modules/update.md](../modules/update.md)

## 背景

检查更新若每次调用 `GET api.github.com/repos/.../releases/latest`，在公开仓未带 token 时仅 **60 次/小时/IP**；开发/E2E 频繁检查易触发 `API rate limit exceeded`。electron-updater 对 github.com **刻意避免 REST**；Tauri 官方推荐 **Release 静态 JSON**。

## 决策

`yohu-update::github::GitHubReleaseProvider` 按序尝试，**任一步成功即返回**：

1. **静态 manifest** — `releases/latest/download/update-manifest.json`（别名 `latest.json`）；平台块键名与 Tauri 一致（`windows-x86_64` / `darwin-aarch64` / `darwin-x86_64`）。
2. **Atom** — `releases.atom` 解析最新 entry → 同 tag 的 manifest，或 **约定文件名直链**（`YohuAdbTools_{version}_x64-setup.exe` 等）。
3. **Web Latest JSON** — `github.com/.../releases/latest` + `Accept: application/json` 取 `tag_name` → manifest / 直链。
4. **REST** — `api.github.com/.../releases/latest`，可选 PAT、`If-None-Match`（304 时上抛可读错误）；**最后兜底**。

Release CI（`release.yml`）用 `scripts/build-update-manifest.ps1` 生成并上传 `update-manifest.json`，使生产检查 **默认不走 REST**。

## 不做什么

- 不引入 `tauri-plugin-updater`。
- 不把 PAT 打进安装包；REST 仅兜底 / 下载私有 asset（`url_policy` 不变）。
- 不在 UI 实现第二套检查逻辑。

## 验收

- `cargo test -p yohu-update` 含 atom / manifest / web / api 单元测试。
- `live_check_and_download_from_github` 在无 token 时仍可通过 Atom/Web 路径检查（`--ignored`）。
