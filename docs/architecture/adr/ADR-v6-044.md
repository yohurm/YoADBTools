# ADR-v6-044 — Linux 签收：OpenH264 单独下载、关于页两行、掉线沿用 025

- **状态：** 已接受，并已按文末顺序实现。掉线仍沿用 025，不另写状态机。
- **日期：** 2026-10-10
- **调研：** [重设计-Linux签收缺口.md](../重设计-Linux签收缺口.md)
- **补充：** [ADR-v6-042](ADR-v6-042.md)、[ADR-v6-043](ADR-v6-043.md)、[ADR-v6-025](ADR-v6-025.md)、[ADR-v6-022](ADR-v6-022.md)、[ADR-v6-031](ADR-v6-031.md)、[ADR-v6-034](ADR-v6-034.md)

## 背景

042 让 Linux 在没有 H.264 VLD 时 `dlopen` Cisco OpenH264，二进制不进 `.deb`。核对机上的 `.so` 是手工放进 `~/.local/share/YohuAdbTools/data/openh264/` 的。产品里没有一条让最终用户自己下载的路径。

025 已经规定空目录和 `went_offline`。这台 ATD 上没点过无设备启动和中途拔掉。这不是另一套空态。

031 / 043 要求关于页展示 per-user 安装根。界面没画。`.deb` 的进程在 `/usr/bin`，目录里的安装根是 `~/.local/opt/YohuAdbTools`。

022 的发布仓库是 `yohurm/Windows-YoADBTools`。检查已经带 `os=linux`。关于页把这一行标成「更新通道」，读起来像系统判断错了。

多设备、未授权、第二台 offline 要第二台设备。这台 VM 没有。拖出仍不交付。

## 决策

### 1. OpenH264 由用户点一下才下载

沿用 042 的许可闸门。补上「谁去下」。

1. **不打进 `.deb`，进程启动时也不下。** 不开投屏的人不会拉这份专利二进制。默认开关是开，不能把「开关默认开」当成用户已经要求下载。
2. **下载动作只有一处。** 没有 VLD、开关开着、`locate` 找不到文件时，洞的标题仍是「没有画面」，正文仍是缺二进制的说明，并多一颗「下载 OpenH264」。设置里同一行开关旁边是同一颗按钮。两处调用同一个命令。
3. **这一下是最终用户的单独下载。** 只从 `ciscobinary.openh264.org` 取 x86_64 的 `libopenh264-2.4.1-linux64.7.so.bz2`。不跟随到别的主机。ARM 在钉住 Cisco 的对应文件和哈希之前，命令失败并说明，不用 x64 文件顶替。
4. **版本钉在解码器已经调用的虚表。** `DecodeFrameNoDelay` 在 2.4 虚表第 4 项。不随手下 2.6。实现时把这份 bz2 的 SHA-256 写进命令，对不上就丢掉，不 `dlopen`。哈希在实现那一笔里记录，不在本页编一个。
5. **落盘走 034。** `yohu-download` 写字节。解压、校验、原子改名放在壳的 `mirror.openh264.acquire`，不放进 `yohu-update`（022 只编排 GitHub Release）。成功后的文件是数据目录 `openh264/libopenh264.so.7`。压缩包放 `cache/openh264/`，成功后删除。`YOHU_OPENH264` 仍只是 `locate` 的覆盖，不是下载目标。
6. **开关关掉就取消进行中的下载**，洞走 042 已有的「已关闭 OpenH264 …」说明。下载成功不自动 `mirror.start`。用户再点「开始」，走现有的 OpenH264 出画。
7. **控制界面的字样和关于页全文不改。** 仍是 `OpenH264 Video Codec provided by Cisco Systems, Inc.` 和已经贴上的许可全文。

### 2. 无设备和掉线沿用 025，不另做一套

核对时看到的就是现在的文案和行为：

| 情形 | 期望 |
|------|------|
| 启动时目录为空 | 设备栏标题「无设备」，说明「连接设备并授权后刷新」，状态「无在线设备」。没有错误对话框 |
| 扫描失败 | 状态「设备扫描失败」，空态上有「重试扫描」。不和「无设备」混成一句 |
| 浏览、采集或投屏中这台从目录消失 | 只停这个 serial。日志退订并冻住已画行。投屏清播放并给出掉线说明。文件槽 detach，已画出的清单留到下一次列表 |
| 扫描又看到这台 | 卡片回来。采集和投屏不自己重新开始 |

再开模拟器仍是 `-accel off`。不新增掉线向导，不在重连时自动 `log.capture.start` 或 `mirror.start`。

### 3. 关于页写两行路径

安装根的定义不改：Linux 仍是 `~/.local/opt/YohuAdbTools`（043）。不把 `app_install_root` 改成 `/usr`。

关于页补两行：

- **安装根：** `paths.install_dir`。`.deb` 安装时这个目录可以还不存在。行下说明它是 per-user 安装根，不是这次进程的文件。
- **本次程序：** 运行中的可执行文件，`std::env::current_exe`。`system.info.paths` 增加 `executable`。`.deb` 上它是 `/usr/bin/YohuAdbTools`。这一行是诊断，不是安装根。Windows / macOS 同样填，安装根那一行仍不跟进程路径走。

### 4. 发布仓库保持 022 的名字，关于页改标签

不改 `yohurm/Windows-YoADBTools`。检查身份仍是 `os` 与 `arch`，Linux 资产仍是 `linux-x86_64` / `linux-aarch64` 的 `.deb`。安装仍是 `xdg-open`，不静默覆盖。

关于页这一行的标题从「更新通道」改为「发布仓库」。仓库迁到别的 slug 时修订 022，不靠本页暗示。

### 5. 第二台设备和拖出

多设备并行、未授权、目录里的 offline，要第二台真实设备，或一台能再开一份模拟器并且能制造未授权态的机器。这台核对 VM 没有第二台物理设备，嵌套 KVM 不能开。不在单一 ATD 上把「未授权」或「多选」记成通过。

拖出保持 043：Linux 返回「拖出仅支持 Windows 与 macOS」。

没有 `/dev/dri` 时 VA-API 这条不作为签收失败。出画验收走 042 的 OpenH264。`hevc` 保持 `false`。

## 明确不选

| 方案 | 为何不在这一 ADR |
|------|------------------|
| 启动时静默下载 OpenH264 | 默认开关是开的，等于没问过用户 |
| 每次启动的模态框 | 挡住不用投屏的人 |
| 把 `.so` 打进 `.deb` 或改 `Caps.id` | 042 / 030 / Cisco 第 1 条 |
| 下载成功就自动开始投屏 | 开始仍是用户动作 |
| 关于页只写 `/usr/bin` 或只写 `~/.local/opt` | 两句里会有一句是假的 |
| 把发布仓库改成 `YoADBTools` | 那是 022 的修订，等 Release 迁走再做 |
| Linux 上静默 `dpkg -i` | 043 §4 |
| 为了签收再写一套掉线状态机 | 025 已经是这套 |
| 在这台 VM 上伪造第二台设备 | 签收会变成假的 |

## 实现顺序

设计接受之后才改代码，按这个顺序，不插别的产品改动：

1. `paths.executable` 与关于页两行；「发布仓库」标签。
2. `mirror.openh264.acquire`：允许的主机、钉死的 URL、SHA-256、解压、原子改名、取消。洞和设置共用按钮。下载成功后仍由用户点「开始」。
3. 再核对：停掉 ATD 看空设备栏；`-accel off` 拉起来；浏览、日志、投屏各做一次掉线再上线；把 `.so` 挪走看缺文件说明和下载按钮，放回后出画。第二台设备不在这台 VM 上补。

## 后果

- 042 的许可闸门补上获取方式。缺文件时的洞标题不变。
- 043 的安装根定义不变。关于页同时展示安装根和本次程序。
- 025 的掉线语义不变。签收要补的是点按，不是新模块。
- 拖出、HEVC、FFmpeg、第二台设备的限制仍在。单台 ATD 全绿也不等于这些行可以签。
