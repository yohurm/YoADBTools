# ADR-v6-030 — macOS 投屏与拖出交付像素

- **状态：** 已接受
- **日期：** 2026-09-05
- **补充：** [ADR-v6-028](ADR-v6-028.md)、[ADR-v6-029](ADR-v6-029.md)、[ADR-v6-024](ADR-v6-024.md)、[ADR-v6-027](ADR-v6-027.md)

## 背景

028 把解码钉在编译期系统 API，并把 Mac/Linux 写成占位：`spawn_unimplemented` 丢掉 `Layout`/`BindPipe`，`hevc=false`。029 把工作台扩到 macOS，但投屏与拖出仍明确「不交付」。

crate 图、IPC、YoUI、Windows MF 热路径已经是对的。缺的是 Mac 壳适配器：VideoToolbox 必须真正出画，Finder 拖出必须能把设备文件拖走。Linux 仍不进入产品。

## 决策

1. **产品目标 = Windows x64 + macOS（Apple Silicon / Intel）。Linux 投屏/拖出仍预留。** 不为 Linux 填 FFmpeg 或 OpenH264 当「原生后端」。
2. **macOS 投屏交付像素。** `cfg(target_os = "macos")` → VideoToolbox（`VTDecompressionSession`）解码 Annex-B，嵌入主窗 `NSView`（Tauri `ns_view()` 的兄弟视图，叠在 WKWebView 透明洞上）。占用 / chrome / `bound` 仍走与 OS 无关的 `Stage` + `scale`。可见卡片是 occupancy 圆角层；画面画在 `dest`。禁止 FFmpeg / libavcodec / `ffmpeg-next`。
3. **HEVC 来自本机。** `Caps.hevc` = `VTIsHardwareDecodeSupported(hvc1)`。`mirror_plan` 仍按此回退 H.264。Windows 继续用 MFT 探测。
4. **`PresentHost` 仍是 OS 无关调度。** `set_owner(owner: isize)`：Windows = `HWND`，macOS = `NSView*`。`GeomHost` 仍只在 Windows 上存在（主窗 subclass 必须在安装它的线程；保持 `PresentHost` 的 `cfg(windows)` 字段，不为跨平台拆掉）。Windows 热路径继续直接调 `MfDecoder`，不上 vtable。
5. **macOS 拖出。** 先 `TransferRunner` pull 到 `drag-out` 会话目录，再 `NSDraggingSession` 提供文件 URL（Copy）。不是 OLE `GetData` 承诺；大文件会在拖开始前拉完。Linux 仍返回明确错误。
6. **AppKit 只在主线程。** 呈现线程拉 `FramePipe`、喂 VT；`NSView` 的创建 / frame / `NSImage` / 事件监视经 `dispatch_sync` 主队列。禁止在后台线程碰 AppKit。

## 管道

```text
设备 MediaCodec Annex-B
  → yohu-mirror FramePipe
  → 壳 AnnexBDecoder（编译期）
       Windows : MF + DXGI
       macOS   : VideoToolbox
       Linux   : 预留（028 占位）
  → 壳表面
       Windows : HWND + DComp clip occupancy
       macOS   : NSView 铺满 avail；卡片 occupancy；NSImageView 画 dest
```

## 否决

FFmpeg、把 Windows Present 改成虚函数、在 Mac 上用 CSS `containInZone` 冒充占用、用 WebCodecs 当壳后端、本期交付 Linux 像素。

## 后果

- `probe().id`：Windows `media-foundation`，macOS `videotoolbox`，Linux `vaapi`（仍无画面）。
- 截图走最后一帧 BGRA → PNG；无画面时错误可读。
- 028 §6「Mac 不交付像素」被本 ADR 取代。029「VT 预留 / 拖出仅 Windows」同样被取代。
