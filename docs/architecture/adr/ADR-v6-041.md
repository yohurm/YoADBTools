# ADR-v6-041 — 日志长会话：记录 / 索引 / 视口

- **状态：** 已采纳
- **日期：** 2026-10-09
- **关联：** ADR-v6-006、ADR-v6-007、ADR-v6-016、ADR-v6-021、[modules/logs.md](../modules/logs.md)、[youi.md](../youi.md)

## 背景

环容量到顶之后，每一批仍在主线程上按整窗重扫，并且同一条记录同时住在 Rust 环、JSON 推送、JS 镜像和格式化文档里。滚动条用 `行数 × 行高` 垫出一段假高度，侧轨随溢出开关，ResizeObserver 反复量尺寸。跟流工人退出码 255 时，若再把全文拉回界面，长会话就停在最坏情况。

Android Studio Logcat 的周期缓冲删的是文档头，编辑器只画可见行，滚动条是逻辑行比例。Yohu 保留 `buffer_capacity` 条数上限（虚拟行需要稳定条数），不改成按 KB 裁文本。

## 决策

全文住在设备环里。每个窗口在环旁边持有一条命中序号索引。界面另持一份过滤后的文档，上限与环相同，滚动只改这份文档的可见行。

- **记录：** `RingBuffer` 拥有结构化行。Tag / App 用 `Arc<str>` 驻留。入环移交所有权，不再为批处理克隆整行。导出与 `log.replay` 仍扫这只环（ADR-v6-021）。容量仍是 `buffer_capacity`。
- **索引：** 过滤定义在 UI，命中判定在 `yohu-domain::log_filter_matches`，紧挨环执行。窗口登记 `log.window.bind`。一批进来只追加命中序号。信号在准入时加减，裁出环的行从索引里去掉并减掉信号。暂停只计滞后条数，不把正文推进视口。
- **视口：** `log.window.bind` 把当前过滤下的命中一次装进窗口文档。其后 `log/hits` 的 `tail` 追加进同一份文档，跟尾与否都带正文。暂停由界面不写入。编辑器只格式化文档里已有的行，并只挂载视口那几行。拖动不调用 `log.page`。
- **跟流：** 工人退出码 255 归为可恢复错误。同一 generation 内用环末墙钟 `-T` 重启，不清环、不发 Stopped、不让 UI 重拉全文。掉线才拆槽位。
- **滚轴：** 短名单仍用像素 `YoScroller`。日志清单走行号：滑块 = 可见行 / 文档行数，DOM 里没有全文高的垫片。文档已在本地时，内层高度是视口，簇按滚动偏移重钉到可见行。`state=on` 时侧轨宽度常驻，内容增长不再改视口宽度。跟尾是闩：向上滚松开，钉底再闩上。闩上时滑块贴轨道末端，文档最后一行落在视口底。只有手势离开底部才松开；视口还没钉上时的测量不算离开。离开底部后新行仍进入文档，视口不动，条数记在「条新日志」。文档头被环裁掉时，未跟尾的滚动偏移退回同样的行数。

ADR-v6-006 的「每设备一路、窗口各有过滤」保留。被替换的是「UI 镜像整环再过滤」。ADR-v6-007 的批量与丢推送不丢环保留；推送体改为命中通知。

## 后果

过滤变更走一次 `log.window.bind`，把过滤后的文档换上。环满之后主线程只追加命中并裁文档头。软换行的滚动比例用可视行，记录上限仍是消息条数。
