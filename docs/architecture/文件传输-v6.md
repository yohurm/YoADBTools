# 文件传输方案（v6 重立）

> **状态：** 已按本文落地  
> **范围：** 本机 ↔ 当前设备文件夹的全部进出：对话框上下载、Explorer/Finder 拖入拖出、进度、清单对账、YoToast 传输通知  
> **取代：** 自造 `window/drag`、DropSurface 点-in-盒热态、`elementFromPoint`。拖出协议细节仍见 [文件拖拽-v6.md](文件拖拽-v6.md) + ADR-v6-018。  
> **约束：** 不新增 `dropIn`；不接 HTML5 drop；不关 `dragDropEnabled`；YoUI 零业务；`SafetyRoot` 只在 core；`transfer_runs` 寿命不变。

---

## 0. 一句话

文件页只展示设备。本机一侧永远是资源管理器。  
进出只有一种作业：**TransferJob**（push 或 pull）。  
四个入口，不是四套引擎。

| 入口 | 本机角色 | 作业 |
|------|----------|------|
| 工具栏「上传」 | 系统开文件框，路径当时已在磁盘 | Push |
| 工具栏「下载」 | 系统存文件框 | Pull（带清单 `expected_bytes`） |
| Explorer / Finder 拖入 | wry 已是 drop target；官方 `onDragDropEvent` | Push |
| 列表拖出 | 壳虚拟文件；Windows 在 GetData 后才有本机字节 | Pull |

虚线不是装饰，是 **DropSession 热态**。热 = 文件页已挂载 ∧ 有在线设备 ∧ 官方拖入未 leave。坐标错了也必须亮，否则作业入口没接通。

---

## 1. 为什么上一版是错的

把「有没有拖进来」绑在坐标命中上，再自造第二条事件。

```text
wry IDropTarget
  → Tauri 把 WindowContent 合成 WindowEvent::DragDrop
  → Tauri 同时发 tauri://drag-enter|over|drop|leave     ← 官方唯一源
  → 壳再 emit window/drag
       get_webview_window(label) 失败则静默 return      ← 事件直接丢
  → FileView 只订 window/drag
  → resolveDropAt：点必须落在 explorer 盒才热
       物理点 / 标题栏偏移 / DPI 任一不对 → 永不热
  → 用户看见：拖进去，面板虚线没了，文件也不上
```

对照（2024–2026 公开设计，不是猜测）：

| 来源 | 做法 | 我们怎么用 |
|------|------|------------|
| [Tauri 2 `getCurrentWebview().onDragDropEvent`](https://v2.tauri.app/reference/javascript/api/namespacewebview/) | 官方把 wry 拖放收成 enter/over/drop/leave；`position` 是 PhysicalPosition | L1 **只订这一路** |
| [Tauri #10744](https://github.com/tauri-apps/tauri/issues/10744) | 拖放点相对窗口/webview/标题栏会偏 | 热态不依赖点 |
| VS Code `EditorDropTarget` + `DropOverlay` | enter 开 overlay；leave/end 关；坐标只摆 overlay | DropSession = overlay |
| [WebView2 `AllowExternalDrop`](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2controller4) | wry 挂了 IDropTarget 后 HTML5 drop 死 | 禁止改接 `ondrop` |

并行的另一堆（进度 / 清单）上一轮已收口，本文 L3/L4 保持。

## 2. 五层（自底而上）

```text
L0  原生源        wry IDropTarget / OLE / Finder
L1  官方拖放      getCurrentWebview().onDragDropEvent → 原样转发
L2  投放会话      DropSession（enter 即热；点只细化 dest）
L3  作业          TransferJob = transfer_runs::run → TransferRunner
L4  对账与呈现    listing.request + transfer/progress + TransferToasts（YoToast）
```

依赖只许向下。UI 不拼 adb argv，不读 `DataTransfer.files`。core 不引用 Tauri。commands 只 `require_online` + 转发。壳 **不再** 自造 `window/drag`。

### 2.1 L0 原生源（事实）

Windows：wry 对 WebView2 **子 HWND** `RegisterDragDrop`。`DragEnter/Over/Drop` 的点经 `ScreenToClient(该 HWND)`，单位是该窗客户区物理像素。挂了这套之后 `AllowExternalDrop=false`，页面 HTML5 drop 收不到完整路径。

tauri-runtime-wry 2.11：

```text
WebviewKind::WindowContent  → SynthesizedWindowEvent::DragDrop
                           → WindowEvent::DragDrop
                           → 框架 emit tauri://drag-*
其它 webview               → WebviewEvent::DragDrop
```

主窗是 `WebviewWindow` = WindowContent。官方 JS API 已经订在这条上。  
macOS：同一套合成规则。  
OLE 拖出与 wry 拖入是两条本机角色，禁止合成一个「拖拽模块」。

### 2.2 L1 官方拖放（单一出口）

`@yohu/api` `onNativeDragDrop` **只** 调 `getCurrentWebview().onDragDropEvent`，`handler(payload)` 原样转发。禁止几何换算。

```text
tauri://drag-enter  { paths, position }
tauri://drag-over   { position }
tauri://drag-drop   { paths, position }
tauri://drag-leave
  → NativeDragDropEvent = 官方 DragDropEvent（position 仍是物理点）
       enter { paths, position }
       over  { position }
       drop  { paths, position }
       leave
  → files dest 才 cssPointFromPhysical(position, scale)
```

契约：

| 项 | 规定 |
|----|------|
| 事件源 | 官方 webview 拖放；禁止自造 `window/drag` |
| 点的空间 | 官方 payload 为物理点；与 `getBoundingClientRect` 对齐的 CSS **只用于目录 dest** |
| 换算 | files dest：`physical / scale`（调用方传入 scale，scale≤0 当 1）；api 禁止换算 |
| 不是 AppEvent | 不进事件环、不进任务中心、不进 `event_names` |
| 权限 | `core:event:default` 已含 listen |

不在壳再 hook `on_window_event` / `on_webview_event` 转发。不重试 listen。

### 2.3 L2 DropSession（第一公民）

投放是**会话**，不是「光标下是谁」。VS Code 对外部文件也是 enter 出 overlay，不是 `elementFromPoint`。

```text
DropSession
  idle          冷
  { hot, dirName }
                热。dirName = 当前可见目录行命中，否则 null（当前 path）
```

状态机：

```text
dropSessionForEvent（不读矩形）
  leave ∨ drop ∨ 无设备 ∨ 模态  → idle
  enter / over 且可投           → 立刻 hot（虚线）

dropCommit（只在松手读目录行盒）
  可投 ∧ paths≠∅  → dest = 命中目录名或当前 path
```

over 的目录行高亮仅当设置 `files_drop_into_folder` 开时用 rAF 合并。`adoptDropSession` 保住已有 `dirName`，禁止每次 over 刷成 `null` 再等 rAF。命中走清单下标 + 滚轴盒（`destDirFromEntries`），禁止扫可见行 `getBoundingClientRect`。enter 也可预约同一帧 dest。默认进当前目录。禁止在 enter 同步读行盒。

**热态绘制（虚线的定义）：**

- session.hot → 清单 `YoPanel edge="drop"` **一定亮**。
- 虚线是填充盒**外**一圈 YoCorner halo（`edgeOutset`），与 hairline 描边不是同一条路径。禁止 CSS `outline` 直角环，禁止把虚线画在面板边界上，禁止模块 class / 子孙选择器改 `--yohu-corner-edge`。
- 另有 folder dest → `YoVirtualList.hotKey`（行底 `YoListRow fill=hot` + `YoListFrame` 叠加框）。禁止模块 `--drop`。
- idle → `edge` 回到 none。leave / drop 之后立刻冷。

不点库根 `.yohu-panel` / `.yohu-empty-state`。token 由 YoPanel L4 写入：`--yohu-accent` 虚线 + `--yohu-accent-soft` 底。

松开：

```text
commit          → fileStore.pushLocals(paths, dest)
无 commit       → YoLog.info，不 push
```

每个本机顶层路径一次 `files.push`。目录交给 `adb push` 递归。不新增命令。

无设备 / 文件页未挂载 → 冷。未挂载不订官方拖放。

### 2.4 L3 TransferJob（唯一寿命）

入口无论对话框还是拖，都进同一扇门：

```text
commands/files  require_online
  → transfer_runs::run
       allocate id + CancellationToken
       任务中心 register
       TransferSpec { id, serial, direction, local, remote, expected_bytes? }
       TransferRunner.run
       release + finish
```

- 对话框 / 拖入：`spawn` = `tokio::spawn(run)`，立刻回 id。
- 拖出 Windows：`GetData` 时 `block_on(run)`。
- 拖出 macOS：`NSDraggingSession` 前 `run.await`。

禁止在 dnd 再写发号。禁止第二套 push/pull。

**进度泵（core，UI 不扫文案）：**

```text
logcat     AdbClient.stream_lines            只 stdout
传输       AdbClient.stream_progress_lines   stdout ∪ stderr
```

adb 的 `(N bytes in …)` / `[ N%]` 在 stderr。目录摘要 **累加** completed，禁止 `max()`。`[N%]` 只在已知 `expected` 时写成 inflight。单文件 pull：清单 size → `expected_bytes`；另 200ms 扫本机文件长度。Push 文件用本地 metadata；Push 目录总量未知，进度不定态直到摘要行。

`TransferProgress.name` = 远端末段，**第一帧就带**。UI 禁止 `setTransferName`。

**终态字节：** Running / Failed / Cancelled 只报观测（摘要行累加 + 已知总量时的 `[N%]` inflight + pull 扫 dest）。禁止 `bytes==0` 用 `expected` 顶，禁止 `bytes.max(expected)`。仅 Done 且本机是文件时写 `metadata.len()`（push=源，pull=dest）；目录或读不到保持观测。

**fault：** 已删 `TransferProgress.message`。失败带 `fault: TransferFault`（内部 tag `kind`，分类 + 路径/serial，零用户句子）。Cancelled / Done 无 fault。`FileError` → `TransferFault` 只在 `TransferRunner::wire_fault`；`fault.rs` 不依赖 protocol。坞文案走 `transferFaultText`，不与路径栏 `filesFaultText` 合并。

**Join：** `JoinError` → `FileError::ProgressJoin`（不是 `Adb::Io`）。每次 `run` 恰好一条终态（校验失败也可无先 Running）。sink 已死：Done 回 `ProgressClosed`；失败仍回原 `FileError`。`ipc_file` 点名 `ProgressJoin → Internal`。

Running：200ms `try_send`（可丢）。终态：`send` 必达。取消杀进程树。Pull 失败/取消删本机目标。

### 2.5 L4 对账与呈现

**清单只有一个主人：`requestListing(reason)`。**

| reason | 何时 | 规则 |
|--------|------|------|
| `bind` | serial **变化** | 回到 `/sdcard`；同设备 `selected()` 新数组不扫 |
| `attach` | 文件页卸了再挂、serial 未变 | 补一次；不靠设备栏重绑 |
| `user` | 刷新钮 / 快捷键 | 立即 |
| `mutate` | 删除 / mkdir / create 的 `finally` | 必达；成功 list **不擦** mutate 错误 |
| `transfer` | 作业终态 | 300ms 合并；任何真正的 `loadListing` 取消未触发的节流 |

`browse_runs` 仍后一次取消前一次。取消不是失败。  
删除：先按名从当前表摘掉，再 IPC，再 `mutate` list。  
`navigate`（进目录 / 地址栏）走 `loadListing(target)`，失败不改当前表。

**传输作业出生：** `files.push` / `files.pull` 立刻回 id。`transfers.ts` `adoptJob` 用当时已知的本机/远端末段建 `TransferJob`。`transfer/progress` 只补字节、态与 `fault`，禁止把已有名打成 `上传 #id`，禁止 `message ?? fault`。

**传输通知：** `TransferToasts` 只读 `transfers[]`，把每条作业同步进文件页 `YoToaster`。运行中 `sticky`；关钮走 `transferStore.dismiss`（运行中即取消）。explorer / preview 的 pane `overflow=hidden`。模块 CSS 禁止 `overflow:auto|scroll`。百分比 / 不定态 / 色 / 文案在 `transfer-model`。终态停留 `DISMISS_HOLD_DURATION` 后摘卡，Toast 播出场。禁止再铺页面传输坞。

## 3. 设计后全链路

### 3.1 拖入（Explorer → 设备）

```text
Explorer CF_HDROP
  → wry IDropTarget（WebView2 子 HWND）
  → WindowEvent::DragDrop
  → Tauri 官方 tauri://drag-*
  → @yohu/api onNativeDragDrop
  → FileView dropSessionForEvent / dropCommit
       enter → DropSession 热 → 虚线
       over  → 可选目录行高亮
       drop  → pushLocals → files.push × N
       leave → 冷
  → TransferJob（与对话框上传同一条）
  → transfer/progress
  → 终态 requestListing(transfer)
```

### 3.2 对话框上传 / 下载

```text
dialogOpenFile / dialogSaveFile
  → files.push / files.pull（pull 带 expected_bytes=条目 size）
  → TransferJob
  → 同上进度与清单
```

### 3.3 拖出（设备 → Explorer）

协议不改 ADR-v6-018：Windows 描述符 + GetData 才 pull；macOS 先物化再文件 URL。  
寿命必须 `transfer_runs::run`。失败不启动 `DoDragDrop` / `NSDraggingSession`。树触顶 `TreeLimit` / `TreeDepth` fail-closed。  
macOS 物化 Ok 后每个 top-local 必须 exists；缺 → `FileError::Local`，不开 `NSDraggingSession`。禁止 `exists` 后 `continue`，禁止把物化后缺失说成 `NotReady`。

### 3.4 删除 / 新建

```text
乐观摘名（仅删除）
  → files.delete / mkdir / create
  → finally requestListing(mutate)
```

## 4. 层职责

| 层 | 做 | 不做 |
|----|----|------|
| wry / OLE | 路径 + 物理点；拖出虚拟文件 | SafetyRoot；发号 |
| Tauri 框架 | WindowEvent → `tauri://drag-*` | 业务 dest |
| `transfer_runs` | 作业寿命 + 任务中心 | 解析 stderr 文案（那是 runner） |
| `TransferRunner` | argv、观测字节、Done 本机长度、`wire_fault`、终态必达、清理 | Win32；`expected` 填 bytes；`err.to_string()` 进 wire；JoinError 装 `Adb::Io` |
| `@yohu/api` | `files.*` + 官方拖放原样转发 | 命中；自造事件；几何换算 |
| `drop.ts` | DropSession 热态纯函数；松手才读行盒；dest 换算物理点 | `elementFromPoint`；IPC；点-in-盒当热门 |
| `transfers.ts` | Job 入口、listing.request、订 progress | 自己算百分比色；补 fault；`message ?? fault` |
| `FileView` | 挂载时订官方拖放、画热态、对话框选路 | OLE；第二套 list |
| `TransferToasts` | 同步进 YoToast；失败明细 `transferFaultText(job.fault)` | 发 push/pull |
| YoUI | Panel overflow、Scroller、ProgressBar | 文件业务 |

壳 `dnd/` 只做**拖出**（OLE / Finder）。拖入不再进壳。

## 5. 不做什么

- 在 FileView 再加 `pointInElement` / `elementFromPoint` / 第三次坐标修正。
- 用点是否在 explorer 盒决定虚线亮不亮。
- 自造 `window/drag`，或 UI 同时订 `tauri://drag-*` 与自造事件。
- 关 `dragDropEnabled` 改 HTML5 `ondrop`。
- 新增 `files.dropIn`。
- 本机双栏、Move、应用内拖到另一目录、丢 `.apk` 当 install。
- 在 `@yohu/ui` 做通用 DnD。
- core 引 Tauri；commands 出现 OLE 类型。
- 每张传输卡绑一次 `files.list`。
- 恢复 `TransferPanel`、`withSerial`、`setTransferName`、目录进度 `max()`。

## 6. 现状对照

| 现象 | 根因 | 不是 |
|------|------|------|
| 拖入无虚线、松手无上传 | 自造 `window/drag` 可静默丢；热态被点-in-盒否决 | 虚线 CSS 被误删 |
| 有事件仍不亮 | 热态写成「点必须在 explorer」；标题栏/DPI 一偏就冷 | 需要再叠一道 hit |
| 进度假 | 曾只泵 stdout | UI 要扫 stderr |
| 删完列表旧 | list 多主人 + 失败不刷新 | 只加 `refresh()` |

## 7. 验收

1. 资源管理器拖文件进入主窗、文件页已打开且已选设备：虚线立刻出现，直到离开或松开。点偏了也必须亮。
2. 拖到目录行：虚线仍在，该行另有高亮；松开进该目录。点不可用则进当前目录。
3. 未选设备 / 删除或新建对话框打开：无虚线，不 push。
4. 对话框上传与拖入同一套进度卡、同一套终态 list。
5. 目录 push 字节累加，不是停在第一个文件。
6. 删除后表与设备一致；失败 toast 不被随后的成功 list 清掉。
7. 拖出仍走 `transfer_runs::run`；取消不删设备源。
8. 小文件成功且无摘要行：Done 条 = 本机文件长度，不是事先 `expected`。
9. 取消/失败条停在观测（常见为 0）；失败 Toast 是分类+路径，JSON 无 `message` / Display 句。
10. 进度任务 join 失败 → Failed + `progress_join`，不是 Io。mac 物化后缺 top-local → `Local`，不开 Finder 会话。

真机与 Tauri 壳验收。Chrome 验证不了 wry / OLE。

## 8. 落地（已按此替换）

1. **L1** `@yohu/api` 只订官方 `onDragDropEvent`。删壳 `native_drop` / `window/drag`。
2. **L2** `dropSessionForEvent`：enter 即热；`dropCommit` 只在松手读目录行。
3. **L3** 进度泵保持 stdout∪stderr + 累加 + `name` / `expected_bytes`。
4. **L4** `requestListing` + `TransferToasts`（YoToast）。
5. **文档** 本文为作业单源；[files.md](modules/files.md) 只留模块能力；[文件拖拽-v6.md](文件拖拽-v6.md) 管拖出协议。
