## 2. 现有架构里已经接上的部分

### 2.1 解码与许可

`mirror_present/linux/openh264.rs` 的 `locate` 只认 `YOHU_OPENH264`，以及数据目录 `openh264/` 下的 `libopenh264.so.7`（兼看 `.so.8` / `.so.2`）。找不到就 `PresentError::OpenH264Missing`。设置开关 `mirror_openh264` 关掉则 `OpenH264Disabled`。洞标题保持「没有画面」。关于页已经贴了 Cisco `BINARY_LICENSE` 全文。`.deb` 不含这份 `.so`。

调用的是 2.4 那份 `ISVCDecoder` 虚表（`DecodeFrameNoDelay` 在第 4 项）。版本不能随手下到 2.6 再指望虚表还在同一格。

### 2.2 目录与掉线

025：`adb devices -l` 是目录。离开 Online 的同一批 `went_offline` 停采集、投屏、浏览，并推 `device/offline`。

界面已经接上：

- 设备栏空目录的标题是「无设备」，说明是「连接设备并授权后刷新」。状态行是「无在线设备」。扫描失败是另一句「设备扫描失败」，带「重试扫描」。
- 日志 `unsubscribeSession`：`capturing=false`，已画出的文档冻住，不删行。
- 投屏把该 serial 的播放清掉，错误句是设备掉线。
- 文件 core 按 serial detach。清单模块不另听掉线，已画出的行留到下一次 `files.list`。

回来靠下一次扫描把卡片放回目录。采集和投屏不因卡片重新出现而自己点「开始」。这和 006 / 016 的「开始是用户动作、世代要显式」是同一条。

### 2.3 路径与更新

`app_install_root` 在 Linux 上是 `$HOME/.local/opt/YohuAdbTools`。`system.info.paths.install_dir` 就是这一条。关于页现在画版本、发布仓库、标识、版权、许可全文、应用日志，不画 `install_dir`。

已安装的 `.deb` 把主程序放在 `/usr/bin/YohuAdbTools`，sidecar 在 `/usr/lib/YohuAdbTools/tools/`。043 写明关于页展示 per-user 安装根，不把当前进程路径当成安装根。两条路径同时为真。

更新检查固定仓库 `yohurm/Windows-YoADBTools`（022）。manifest 键在 Linux 上是 `linux-x86_64` / `linux-aarch64`。安装是 `xdg-open` 打开 `.deb`（043 §4）。这次核对日志是 `os=linux arch=x86_64`，随后「已是最新版本 version=0.1.3」。

## 3. 对照

### 3.1 OpenH264 怎么到用户机器上

来源仍是 Cisco `BINARY_LICENSE.txt` v1.0，以及 [调研](调研-Linux投屏呈现与私有软解.md) §5。专利授权只覆盖 Cisco 发布的那份二进制，并且要单独下载到最终用户的设备上，下载之前不和第三方软件打在一起。用户必须能打开、关掉、再打开。控制界面上有那一行 Cisco 字样。许可全文要在用户能看见的地方。

| 做法 | 谁发起下载 | 对这条许可 | 对我们 |
|------|------------|------------|--------|
| 打进 `.deb` | 没有单独下载 | 第 1 条不允许。030 也不许拿它当原生后端 | 不选 |
| 进程一启动就静默 GET | 应用，用户还没碰到投屏 | 「单独下载」被读成应用自己拉。默认开关已经是开的，等于没问过 | 不选 |
| 每次启动弹窗 | 用户必须先回答 | 问过了，但终端和文件用户也被挡住 | 不选 |
| Firefox GMP | 要用到 H.264 时从 Cisco CDN 拉插件；附加组件里能关 | 运行时单独下载，控制面在产品里 | 借「运行时、单独、能关」。不借「一进需要解码的页面就自动拉」 |
| Fedora `fedora-cisco-openh264` | 用户用包管理器从 Cisco 的仓库安装 | 发行版不托管二进制 | 我们的 `.deb` 不是发行版仓库，借不了这条安装路径 |
| Debian contrib | 安装那个包时再下 Cisco 的库 | 源码可以在 main，二进制不进 main | 借「主包不含二进制」 |
| 洞里和设置里同一颗按钮，用户点了才下 | 这一下是最终用户的下载 | 单独、可关、字样和全文都还在 042 | 选这条 |

官方文件已经在核对说明里：`http://ciscobinary.openh264.org/libopenh264-2.4.1-linux64.7.so.bz2`。x86_64 就钉这一份。ARM 不拿 x64 的文件顶上。

HTTP 落盘已经有 `yohu-download`（034）。更新编排留在 `yohu-update`（022），不把 Cisco 的 URL 塞进 GitHub Release 流程。

### 3.2 无设备和掉线

scrcpy 和 Android Studio 的设备栏都是：目录空就空态；设备从 `devices` 里消失就停这条会话，已有输出留在屏幕上；设备再出现不自动把上次的 logcat 或投屏重新开起来。025 已经是这个模型。再做一个「掉线向导」或自动续采，会和「开始是显式动作」叠成两套。

核对时要把模拟器停掉再开应用，看的是这套已经写好的文案，不是新文案。再开时仍是 `-accel off`。

### 3.3 关于页的两条路径

VS Code 关于页写的是当前安装的位置。Windows 的本产品故意不跟进程路径走，安装根是 `%LOCALAPPDATA%\Programs\…`（031）。Linux 的 `.deb` 让「目录里的安装根」和「这次进程的文件」分开了。合成一行会有一句是假的。两行各写各的事实，安装根的定义仍是 043 的 `~/.local/opt`。

### 3.4 发布仓库的名字

仓库 slug 是 022 的发布主机，不是当前系统。检查身份是 `os` 和 `arch`，资产名是 `linux-x86_64` 的 `.deb`。把 slug 改成 `YoADBTools` 是 022 的另一次修订，等 Release 真的迁过去再改。关于页把这一行标成「发布仓库」，读者就知道这是仓库名。

## 4. 本页不改的行为

- 拖出仍是「拖出仅支持 Windows 与 macOS」。
- `Caps.id` 仍是 `vaapi`。`hevc` 仍是 `false`。没有 FFmpeg。
- 没有 `/dev/dri` 仍走 CPU 出画，不是失败。
- 多设备、未授权不在这台 VM 上造假设备。目录模型不改。
- 不把 `app_install_root` 改成 `/usr`。
- 不静默 `dpkg -i`。
