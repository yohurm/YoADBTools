## 1. 现状（设计前）与问题

同一窗口内容有两条并行投递通道：

- `log/hits`：增量（`tail` + `total`），逐批追加。
- `log.window.bind`：绑定时刻的全量前缀快照（`through = ring.next_seq()`，只含 `seq<=through-1`）。

两条通道在 IPC 上**无序**，而「文档位置」没有单一所有者：`fromSeq/lastSeenSeq/visible/pendingCount/signalCount/docShift/following/frozenThroughSeq` 分散在 `panel-projection`、`follow-state`、`session-lifecycle` 三个模块写；对账靠 `viewport-page.pageGen` 与命中事件 `bumpPage` 临时互斥，最终由 `applyPage` 盲替换。任一交错即丢行（详见 [架构审查](日志系统架构审查-2026-11-20.md) P0-1/P1-1）。另有三份重复的 head-overlap 算法与两套文档增量实现。

## 2. 目标分层（设计后）

遵守桌面分层 `View → store → 类型化 IPC → commands → domain`，消费投影平面内部按单一职责再分层：

```
View（LogAnalyzerView / editor/*，只渲不判）
  │  读取：LogWindowSnapshot（不可变）      dispatch：LogWindowAction
  ▼
store 装配（workspace / capture 门面，薄）
  ▼
store·文档状态机（新，纯）
  stream/log-window-reducer.ts
    reduce(state, action) -> { state, effects }
    - 唯一文档状态所有者（不可变）
    - 连续 seq 游标：fromSeq / lastSeq 单调
    - 空洞 → effects: [{ type:"reload" }]（自愈，不静默丢）
  stream/seq.ts     唯一 seq 对账原语（已落地）
  stream/log-window-types.ts   LogWindowState/Action/Effect（模型层）
  ▼
store·副作用执行（capture-subscriptions / viewport-page）
  事件 → action；effect → log.window.bind（唯一取页）
  ▼
@yohu/api（类型 + invoke/listen）→ commands → yohu-logsrv（采集平面，不改）
```

### 状态所有权（唯一真源）

| 数据 | 所有者 | 说明 |
|---|---|---|
| 日志全文 | `yohu-logsrv::RingStore`（设备环） | 不变；文档只是缓存 |
| 窗口命中序号 | `yohu-logsrv::WindowBook` | 不变 |
| 窗口文档（rows / 游标 / pending / signal / docShift / follow） | `stream/log-window-reducer` 产出的不可变 `LogWindowState` | **新**：取代 panel-projection + follow-state 双写 |
| 会话 CRUD / 列视图 / 过滤输入 | `session-lifecycle` / store 字段 | 保留（与文档状态无关） |
| 设备桶（世代/溢出/进程索引） | `device-projection` | 保留 |
| 采集相 | `capture-orchestrator` | 保留 |

## 3. 连续 seq 契约（本设计的核心）

- **游标**：`lastSeq` = 文档已画的末 seq（空文档为 `fromSeq-1`）。`fromSeq` = 窗口起点。
- **命中**（`hits.tail`）：
  - `tail[0].seq == lastSeq+1` → 连续，追加。
  - `tail[0].seq > lastSeq+1` → **空洞**：进入 `pendingGap`，dispatch `reload` effect；空洞期间不把越界行静默吞掉，也不假装连续。
  - `tail[0].seq <= lastSeq` → 已画，跳过（幂等）。
- **快照**（`bind` 页）：按 seq 对账——**页为真前缀**，保留当前文档中 `seq > 页末 seq` 且命中当前过滤的行；两侧无重叠即无重复，页补齐空洞即无丢失。
- **溢出**（`log/overflow`）：只是「可能丢推送」的提示；正确性由上面的 seq 契约保证，overflow 不再是对的包唯一恢复入口。
- **暂停**：暂停只挡「入文档」（游标不动），恢复时一次 `reload` 对账补齐。
- **清空 / 掉线**：`fromSeq` 前移、`following` 抬起按各自状态机；均走同一 reducer。

## 5. 分阶段（每刀干净，非半成品）

- **Stage 1（已完成）**：唯一 seq 对账原语 `stream/seq.ts`；`applyPage` 按 seq 对账；删除 `bumpPage` 双代际；空洞自愈。验收：`logs` 用例 + tsc + lint。
- **Stage 2（已完成）**：`stream/log-window-reducer.ts` 成为唯一文档纯状态机（含连续 seq 判定与 `gap`）；`panel.ts` 降为 `export *` 薄门面；`panel-projection`/`follow-state` 仅装配并调用 reducer 原语；删除事件入口 `healGap` 与 `panel.ts` 重复算法。验收：`logs` 356 用例 + 全量 `vitest` + tsc + lint；无 TODO/跳过测试。
- **Stage 3（已核销）**：wire→view 边界——`LogLine` 作为 IPC 纯数据契约跨层（stack-layering 允许的契约孪生，不做多余镜像层）；`LogHits.total` 保留为窗口命中总数（core 批切分不变量诊断，UI 不依赖，非死字段）；文档容量口径——「文档=缓存、环=历史边界」由 `store.test.ts`「容量口径：重绑后只显示环仍持有的行」锁定。

- **不改** `yohu-logsrv` 采集平面内部（槽位/环/窗口索引/批量/跟流）——ADR-047 已闭合，避免无谓 churn。
